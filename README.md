# Throne subscription bridge

Cloudflare Worker для объединения стандартных TXT-подписок из [igareck/vpn-configs-for-russia](https://github.com/igareck/vpn-configs-for-russia) в одну подписку для Throne и совместимых VPN-клиентов. Текущая версия использует только Workers KV: Durable Objects, Cron Trigger, отдельный сервер и платный тариф не требуются для самой архитектуры. Использование Cloudflare ограничено квотами выбранного тарифа.

## Быстрый запуск через Cloudflare Dashboard

**Одного Deploy недостаточно: сначала создайте KV namespace и привяжите его к Worker.**

1. Откройте [Cloudflare Dashboard](https://dash.cloudflare.com/) и выберите свой аккаунт.
2. Перейдите в **Workers & Pages → KV** (в некоторых версиях интерфейса: **Storage & databases → KV**). Создайте namespace, например `throne-subscriptions`. Его название может быть любым.
3. Откройте существующий Worker `blue-dust-abda` в **Workers & Pages**. В разделе **Settings → Bindings** добавьте binding типа **KV namespace**. Выберите созданный namespace и укажите имя переменной строго `SUBSCRIPTIONS_KV`.
4. Если в Worker осталась старая привязка `UPDATE_LOCK`, удалите её. Новая версия не использует Durable Object.
5. Откройте **Edit code**, полностью замените код на актуальный `worker.js` из этого репозитория и нажмите **Deploy**. Не используйте старую версию из истории коммитов. Если Worker развёртывается из Git, настройте сборку/деплой так, чтобы использовался актуальный `worker.js` и этот же KV binding.
6. Откройте `/status?scope=all`. До первой сборки `ok: false` и нулевое количество конфигов — нормальная ситуация: `/status` ничего не скачивает.
7. Откройте `/subscription?scope=all&format=base64`. Первый запрос проверит GitHub и соберёт кэш. После успешного ответа откройте `/status?scope=all` ещё раз: должны появиться `ok: true`, SHA, время сборки и `uniqueProxies` больше нуля.
8. Добавьте URL подписки в Throne и обновите группу. Если Base64 не распознаётся, попробуйте `format=plain`.

Для варианта через Wrangler также нужно указать KV binding в конфигурации проекта. Просто создать namespace без привязки недостаточно. Не добавляйте вымышленные namespace ID: используйте ID своего ресурса Cloudflare.

## Адреса

Для твоего существующего Worker:

```text
https://blue-dust-abda.pertuuuur.workers.dev/subscription?scope=all
https://blue-dust-abda.pertuuuur.workers.dev/subscription?scope=all&format=plain
https://blue-dust-abda.pertuuuur.workers.dev/subscription?scope=black
https://blue-dust-abda.pertuuuur.workers.dev/subscription?scope=white-cidr
https://blue-dust-abda.pertuuuur.workers.dev/subscription?scope=white-sni
https://blue-dust-abda.pertuuuur.workers.dev/status?scope=all
```

`/` также отдаёт подписку. По умолчанию используются `scope=all` и `format=base64`. Base64 содержит только URI-конфигурации; plain дополнительно содержит комментарии с названием профиля, рекомендуемым интервалом, SHA и временем сборки. Оба формата собираются из одного и того же сохранённого набора.

## Как работает обновление

При запросе клиента Worker читает последнюю готовую версию из KV. Если с предыдущей проверки прошло меньше 15 минут, возвращается кэш без обращения к GitHub. Когда окно истекло, Worker получает SHA последнего коммита ветки `main`:

- SHA не изменился — обновляет время проверки и возвращает прежнюю подписку, не скачивая TXT.
- SHA изменился — получает корневое дерево репозитория, находит стандартные TXT-файлы и скачивает их по неизменяемому SHA коммита. Затем фильтрует URI, удаляет точные дубликаты и собирает все области.
- Сборка завершилась успешно — сначала сохраняется новый версионированный snapshot, затем переключается указатель на него. Предыдущая версия остаётся в KV.
- GitHub или один из источников недоступен — новая неполная сборка не публикуется; если уже есть рабочий кэш, клиент получает его. После ошибки следующая проверка разрешена через 5 минут.

Первое обновление после установки может быть заметно медленнее последующих: Worker должен скачать и обработать исходные файлы. Обновление происходит по запросам клиентов, а не автономно по расписанию. Рекомендуемый интервал в Throne — 60 минут; фактическое выполнение таймера зависит от клиента.

### Ограничения KV-only

KV — распределённое хранилище с eventual consistency, а не глобальная транзакционная база. Проверка раз в 15 минут является оптимизацией, но не строгим глобальным лимитом: разные дата-центры могут временно видеть разные версии и одновременно запускать сборку. Внутри одного isolate используется single-flight. Версионированные snapshots и резервный указатель уменьшают риск выдачи частично записанных данных, но не гарантируют атомарную публикацию во всех регионах.

Сохранённые snapshots не удаляются автоматически, чтобы не потерять последнюю рабочую версию. При длительной эксплуатации старые версии можно удалять вручную после проверки текущего указателя и резервной версии. Ограничение размера одного snapshot — 25 MiB; если общий набор превысит его, Worker не опубликует новый snapshot и продолжит использовать старый. Бесплатный тариф также имеет лимиты на чтения, записи и хранение KV, поэтому нулевая стоимость не гарантируется при любой нагрузке.

## Источники и форматы

Worker обнаруживает корневые стандартные TXT-файлы по шаблонам `BLACK_*`, `WHITE-CIDR-*`, `WHITE-SNI-*` и `Vless-Reality-White-Lists-Rus-Mobile`. Папка `Export/` и клиентские JSON/YAML-форматы не смешиваются с универсальной подпиской. Поддерживаются URI со схемами вроде `vless://`, `ss://`, `trojan://`, `vmess://`, `hysteria2://`, `tuic://` и другими; HTTP(S)-ссылки исключаются. Точные дубликаты строк удаляются.

Это агрегатор URI, а не конвертер конфигураций: специфические настройки маршрутизации, правила и проверки из клиентских JSON/YAML не переносятся. Поддержка конкретного протокола зависит от версии Throne или другого VPN-клиента. Для сетей с белыми списками рекомендуется использовать отдельные группы `white-cidr` и `white-sni` вместо смешанного `all`.

## Статус и диагностика

`GET /status?scope=all` не обращается к GitHub и не запускает сборку. Он показывает `ok`, `sha`, `generatedAt`, `checkedAt`, `nextCheckAt`, `lastCheckResult`, `lastError`, `uniqueProxies`, `sources` и `fallback`. После первого успешного запроса подписки `ok` должен стать `true`.

Если Worker отвечает `Missing SUBSCRIPTIONS_KV binding`, проверьте имя привязки и повторно задеплойте код. Если подписка не импортируется, сначала проверьте статус, затем содержимое `format=plain`. Ответ с ошибкой GitHub или пустой список не следует считать корректной подпиской.

## Необязательные секреты

Для обычной работы не нужны ни GitHub token, ни отдельная авторизация. Публичный upstream читается без токена. При необходимости можно добавить секрет `GITHUB_TOKEN` для авторизованных запросов к GitHub API. Не помещайте токены в код, README, URL или публичный репозиторий.

Принудительное обновление доступно только если настроен секрет `REFRESH_TOKEN`. Endpoint `/refresh` принимает исключительно POST с заголовком `Authorization: Bearer <token>`; без настроенного секрета он недоступен. Пример (подставьте свой токен локально):

```bash
curl -X POST \
  -H "Authorization: Bearer YOUR_REFRESH_TOKEN" \
  https://blue-dust-abda.pertuuuur.workers.dev/refresh
```

Не добавляйте `/refresh` как URL подписки и не публикуйте токен. Обычное ручное обновление в Throne не требует этого endpoint и не обходит 15-минутное окно.

## История и развёртывание

Исходный Worker сохранён отдельным коммитом `294a9132a5474e04804bcf9151548535feee8c88`. Последующие коммиты содержат изменения архитектуры, поэтому старую версию можно посмотреть в истории Git. Текущая KV-only версия находится в `main`.

Изменение файлов на GitHub само по себе не означает, что Cloudflare обновил работающий Worker. При ручном развёртывании нужно заменить код в Cloudflare и нажать Deploy. Уже созданные bindings сохраняются при обновлении кода, но новый KV binding необходимо создать и подключить хотя бы один раз.
